# Project access policy

> Fictional example: replace this record with your own information before relying on it.

## Request evidence
An access request must name the project, required role, business reason and approving owner.
The actual identity provider and execution host enforce access; a knowledge record does not grant it. Store request references and approval evidence here, never tokens or passwords.
## Changes
Review access when responsibilities change and follow the real organization's offboarding procedure. Use [the request procedure](../procedures/request-help.md) and [ownership directory](../team/ownership.md) to find the accountable owner.
